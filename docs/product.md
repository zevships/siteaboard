# SiteAboard 产品范围

以下描述目标产品。当前仅交付静态前端与合成示例，已实现范围见 README；真实数据、CLI 和 skills 尚未接入。

SiteAboard 帮助已经上线网站的独立开发者完成“接入 → 看懂数据 → 采取行动 → 复查效果”。优先服务面向海外用户的中国开发者，文档先中文，术语和接口使用稳定英文标识。

## 首批用户

已有 1–5 个工具站、内容站或小型 SaaS，能够运行 Node 项目，使用或愿意使用 coding agent；不想把时间花在连接多个后台、解释指标和重复排查上。这是首批设计对象，不是站点数量限制。

首次价值：使用自己的站点得到一份有来源、时间与缺失说明的数据摘要，完成一个可复查的改进。仅有图表不算完成。

## 首版页面

| 页面       | 回答的问题                 | 首版操作                                        |
| ---------- | -------------------------- | ----------------------------------------------- |
| 总览       | 哪个站点需要我关注？       | 多站摘要、数据截止时间、失败和待复查项          |
| 站点       | 用户从哪来，在哪一步离开？ | 流量趋势、来源、页面、已支持的事件与漏斗        |
| 搜索       | 哪些页面和查询值得检查？   | GSC 表现、变化、证据链接；不把点击数当站点 UV   |
| 改进       | 做过什么，效果如何？       | 问题、改动/发布记录、观察窗口、复查结论         |
| 连接与任务 | 数据为什么缺失或过期？     | 站点配置、凭证检查、同步、失败原因与重试        |
| 操作指南   | 下一步怎么做？             | 接入、埋点校验、复盘、SEO 检查的 agent 操作说明 |

页面和 CLI 均展示未连接、缺失、不支持、同步失败等状态；零值只有在数据确实完整且计数为零时才成立。

## 三条使用路径

1. **体验**：导入明确标注的合成站点；无需凭证和模型调用即可浏览、查询和记录改进。
2. **接入现有统计**：添加站点，授权一种流量来源和 GSC，验证权限与时间范围，完成一次真实复盘。缺少某来源不阻塞其他已接入能力。
3. **自有埋点**：在网站部署接收端、安装事件脚本，验证测试事件与去重，然后由本地管理台同步数据。这条路径需要网站侧工程工作，单独验收。

建站前指导作为后续 skill：检查项目、部署和 SEO 基础，不生成另一个通用 SaaS 模板。已上线的站点运营是首个产品闭环。

## 首版包含与延后

包含本地单用户、多站点、按需同步、数据来源追溯、简单改进记录；普通查询和同步不调用 LLM。

延后团队账号与权限、云端托管、计费、社媒发布、博主采集、视频制作、设备监控、训练平台、知识图谱、插件市场、DSH 适配和内置聊天。

持续监控需要常开的进程；默认不要求用户有专用服务器。关机后补拉历史不等于关机期间持续告警。

## 验证方式

第一轮邀请 5–10 位目标用户试用，记录安装、授权、首次有效数据、首次改进行动和一周后复用情况。样本量与 30 分钟完成基础接入的目标都是试验设计，尚无实测结论；网站端改造耗时单独记录。

通过条件：新用户无需维护者改源码即可接入，能够说明数字来源和下一步行动。若多数人只需要现有统计服务的复盘层，先完善连接器与 skills；不要提前扩大自有采集平台。
